# 安装与快速开始

本文档帮助你完成本地 nanobot 的首条回复。之后你可以添加 WebUI、聊天应用、本地模型、网页搜索、MCP、部署或自定义插件。

如果你从未使用过终端或编辑过配置文件，请先阅读 [`start-without-technical-background.md`](./start-without-technical-background.md)。本文假设你可以熟练粘贴命令和编辑 JSON 片段。

## 准备工作

你需要：

- Python 3.11 或更高版本。
- 一个你可以调用的 LLM provider、公司端点、订阅端点或本地模型服务器。以下示例中仅以 OpenRouter 为例，使代码片段具体化；只要 key、provider 名称和模型 ID 匹配，任何受支持的 provider 都可以使用。
- Git（仅当你从源码安装时需要）。
- Node.js 或 Bun（仅当你开发 WebUI 时需要）。

> [!IMPORTANT]
> 仓库文档可能描述一些仅在源码中可用的功能。日常稳定使用请从 PyPI 或 `uv` 安装；当你需要最新仓库行为或计划贡献代码时，再从源码安装。

## 1. 安装

选择一种安装方式。

**一键安装：**

```bash
sh -c "$(curl -fsSL https://raw.githubusercontent.com/HKUDS/nanobot/main/scripts/install.sh)"
```

在 Windows PowerShell 中：

```powershell
irm https://raw.githubusercontent.com/HKUDS/nanobot/main/scripts/install.ps1 | iex
```

默认命令从 PyPI 安装或升级 `nanobot-ai`，然后启动 `nanobot onboard --wizard`。如果你完成了向导并保存了配置，请跳过下面的手动初始化/配置步骤，直接转到[验证安装](#4-验证安装)。

如需预览安装计划而不改变你的环境，传递 `--dry-run`；结合 `--dev` 可预览 main 分支的安装。

```bash
sh -c "$(curl -fsSL https://raw.githubusercontent.com/HKUDS/nanobot/main/scripts/install.sh)" -- --dry-run
```

```powershell
& ([scriptblock]::Create((irm https://raw.githubusercontent.com/HKUDS/nanobot/main/scripts/install.ps1))) --dry-run
```

如需安装当前 `main` 分支，传递 `--dev`：

```bash
sh -c "$(curl -fsSL https://raw.githubusercontent.com/HKUDS/nanobot/main/scripts/install.sh)" -- --dev
```

```powershell
& ([scriptblock]::Create((irm https://raw.githubusercontent.com/HKUDS/nanobot/main/scripts/install.ps1))) --dev
```

如果 `curl` 或 `irm` 不可用，或者 GitHub raw 下载在你的网络上被阻止，请使用下面的手动安装方式。

如果你想先检查脚本内容，打开 [`../scripts/install.sh`](../scripts/install.sh) 或 [`../scripts/install.ps1`](../scripts/install.ps1)。

**使用 `uv` 安装稳定版：**

```bash
uv tool install nanobot-ai
nanobot --version
```

**使用 pip 安装稳定版：**

```bash
python -m pip install nanobot-ai
nanobot --version
```

**从最新源码安装：**

```bash
git clone https://github.com/HKUDS/nanobot.git
cd nanobot
python -m pip install -e .
nanobot --version
```

如果 pip 安装后 shell 找不到 `nanobot`，使用模块形式运行：

```bash
python -m nanobot --version
python -m nanobot onboard
```

在 Windows 上，文档中的 `~` 表示你的用户配置文件目录，例如 `C:\Users\you`。

文档中使用 `python` 表示命令。如果你的系统将 Python 3.11+ 暴露为 `python3` 或 `py`，请相应替换，例如 `python3 -m pip install nanobot-ai` 或 `py -m nanobot --version`。

## 2. 初始化

如果一键安装已经启动了向导并且你已保存配置，请跳过此节。

```bash
nanobot onboard
```

如果你更喜欢交互提示而非手动编辑 JSON，使用向导：

```bash
nanobot onboard --wizard
```

初始化会创建：

| 路径 | 说明 |
|------|------|
| `~/.nanobot/config.json` | provider、模型、渠道、工具、gateway 和 API 的主设置文件 |
| `~/.nanobot/workspace/` | memory、session、heartbeat 任务、技能和产物的 Agent 工作区 |

如果你已有配置，`nanobot onboard` 可以补充缺失的默认字段，而不会覆盖你已有的值。

## 3. 配置 Provider

如果已在向导中配置了 provider 和模型设置，请跳过此节。

打开 `~/.nanobot/config.json`。将以下块添加或合并到 `nanobot onboard` 创建的文件中；除非你想重置配置，否则不要替换整个文件。

**API key：**

```json
{
  "providers": {
    "openrouter": {
      "apiKey": "sk-or-v1-xxx"
    }
  }
}
```

**模型预设：**

```json
{
  "modelPresets": {
    "primary": {
      "label": "Primary",
      "provider": "openrouter",
      "model": "anthropic/claude-opus-4.5",
      "maxTokens": 8192,
      "contextWindowTokens": 65536,
      "temperature": 0.1
    }
  },
  "agents": {
    "defaults": {
      "modelPreset": "primary"
    }
  }
}
```

预设中的 provider 和 model 必须匹配。以上片段仅为示例。如需使用其他 provider，请一并替换以下值：

| 替换内容 | 位置 |
|---|---|
| Provider 配置 key，如 `openrouter` | `providers.<provider>` |
| API key 或环境变量 | `providers.<provider>.apiKey` |
| 预设 provider 名称 | `modelPresets.primary.provider` |
| 模型 ID | `modelPresets.primary.model` |
| 端点 URL（仅在需要时） | `providers.<provider>.apiBase` |

对于现有配置，直接设置 `agents.defaults.provider` 和 `agents.defaults.model` 仍然有效，但命名预设是推荐方式，因为它们还支持 `/model` 切换和回退链。关于直连、gateway、OAuth、云服务和本地设置等各类 provider 示例，参见 [`providers.md`](./providers.md)。

**`apiBase` / 基础 URL 是什么？**

`apiBase` 是 provider 端点的 HTTP 基础 URL，不是模型名称。nanobot 中大多数托管 provider 已知道其默认端点，所以你通常只需设置 `apiKey` 和模型预设。在以下情况设置 `apiBase`：

- 使用 `custom` 连接第三方或自托管的 OpenAI 兼容 API；
- 使用本地 OpenAI 兼容服务器，如 Ollama、vLLM 或 LM Studio；
- 使用 provider 特定的备用端点、区域端点、代理或订阅端点。

示例：

```json
{
  "providers": {
    "custom": {
      "apiKey": "${CUSTOM_API_KEY}",
      "apiBase": "https://api.example.com/v1"
    }
  }
}
```

```json
{
  "providers": {
    "ollama": {
      "apiBase": "http://localhost:11434/v1"
    }
  }
}
```

如果 provider 的文档说端点是 `/v1`，则在 `apiBase` 中包含 `/v1`。模型 ID 仍然放在当前 `modelPresets` 条目中。

如果你不想在 `config.json` 中存储密钥，可以引用环境变量并在启动 nanobot 前设置：

```json
{
  "providers": {
    "openrouter": {
      "apiKey": "${OPENROUTER_API_KEY}"
    }
  }
}
```

## 4. 验证安装

```bash
nanobot status
```

这应显示 config 路径、workspace 路径、当前模型或预设以及 provider 摘要。它不会向模型发送消息，因此在首次真正请求之前可以先快速检查配置。

按以下方式解读：

| 状态行 | 你期望看到的 |
|---|---|
| `Config` | 对勾 ✓ |
| `Workspace` | 对勾 ✓ |
| `Model` | 你期望的模型或预设 |
| Provider 列表 | 大多数 provider 可以显示 `not set`；当前预设使用的 provider 应显示对勾、OAuth 状态或本地 URL |

## 5. 测试一条消息

运行一条一次性 CLI 消息：

```bash
nanobot agent -m "Hello!"
```

成功的首次运行证明：

- `nanobot` 命令已安装；
- `~/.nanobot/config.json` 可以加载；
- 选定的 provider 和模型可以应答；
- 默认工作区可以创建和使用。

回复文本本身会有所不同。任何正常的助手回答都意味着安装、配置、provider、模型和工作区路径全部可用。

如果成功了，启动交互式 CLI 聊天：

```bash
nanobot agent
```

交互式会话能够正常应答后，nanobot 可以帮助你完成后续设置。让它阅读相关文档、检查你当前的 `~/.nanobot/config.json`，并做一项具体修改，例如启用 WebUI、添加 provider 预设或配置一个聊天渠道。当 nanobot 说配置已更新时，在聊天中运行 `/restart` 或手动重启 nanobot 进程，使常驻进程重新加载 `config.json`。

示例提示：

```text
阅读当前仓库中的 docs/quick-start.md、docs/providers.md 和 docs/configuration.md。
然后更新 ~/.nanobot/config.json，添加一个名为 "primary" 的 OpenRouter 模型预设。
告诉我具体改了什么以及我是否需要运行 /restart。
```

使用 `exit`、`quit`、`/exit`、`/quit`、`:q` 或 `Ctrl+D` 退出交互模式。

## 首次运行故障排查

| 症状 | 检查项 |
|------|--------|
| `nanobot: command not found` | 使用 `python -m nanobot ...`，或将 Python scripts 目录添加到 `PATH`。 |
| `ModuleNotFoundError: nanobot` | 确认你在运行命令的同一个 Python 环境中进行了安装。 |
| JSON 解析错误 | 检查 `~/.nanobot/config.json` 中的逗号和花括号；以上示例是局部片段，需要合并。 |
| 认证或 401 错误 | 检查 API key 是否有效、复制时无空格，并放在你选择的 provider 下。 |
| Provider/模型错误 | 确保当前预设使用的 provider 拥有你的 API key，且该模型在其中存在。 |
| CLI 正常工作但聊天应用不回复 | 首先保持 `nanobot gateway` 运行，然后按照 [`chat-apps.md`](./chat-apps.md) 操作。 |
| WebUI 打不开 | 启用 WebSocket 渠道并打开端口 `8765`，而非 gateway 健康检查端口 `18790`。 |

更完整的诊断流程参见 [`troubleshooting.md`](./troubleshooting.md)。
